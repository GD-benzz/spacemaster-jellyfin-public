# 空间大师 · 安装指南（群晖 / 绿联 / 威联通 / 飞牛 FnOS 通用）

> 空间大师只做转码音频工作，Jellyfin 字幕 / 刮削 / 元数据 / 媒体库 / 用户记录等其它功能均不受影响。

> 前提：您已经在 NAS 上用 Docker 跑着 Jellyfin（jellyfin/jellyfin 或 nyanmisaka/jellyfin 镜像）。空间大师是在它外面加一层音效，不修改 Jellyfin 本体。
>
> ⚠️ 群晖用户特别注意：如果您装的是「套件中心」里的 Jellyfin 原生套件，它不走 Docker，用不了本方案。请先在 Docker 里装 jellyfin/jellyfin，再按本指南操作。

空间大师不会修改 Jellyfin 本体、影片库、账号、原有 `/config /cache /media` 挂载、其它设置。卸载即回到原状（见下文「撤销」）。

---

## 第 1 步｜获取镜像

把下面这个镜像拉到 NAS 本地（各平台入口不同，见括号）：

`ghcr.io/gd-benzz/spacemaster-fnos:v3`

- 群晖 Container Manager：Registry 标签 → 设置 → 添加仓库（填 `ghcr.io`）→ 搜索 `spacemaster-fnos` 下载；或 Image 标签 → 添加 → 从 URL 添加，粘贴上面地址。
- 绿联 UGOS：Docker → 镜像 > 镜像仓库 → 粘贴上面 ghcr 地址拉取（详见系统内的「镜像加速与镜像仓库拉取指南」）。
- 威联通 Container Station：Create → 输入 `ghcr.io/gd-benzz/spacemaster-fnos:v3`（Advanced 模式需同时指定 registry 与 tag）→ 拉取。
- 飞牛 FnOS：Docker → 本地镜像 → + 添加镜像 → 从 URL 添加，粘贴上面地址。

（「镜像仓库」页默认只搜 Docker Hub，直接搜这个名字搜不到，要从 URL / 私有仓库入口拉。）

---

## 第 2 步｜部署（三个容器）

无论哪个平台，部署都分三块：① 建控制台容器 ② 给已有 Jellyfin 接上 ③ 加 proxy。下面先讲三块「填什么」，再讲各平台「在哪点」。

### 2.0 建共享文件夹 smdata

在 NAS 的共享文件夹下新建子目录 `smdata`，这是控制台和 Jellyfin 共用的数据区（音效参数、日志）。各平台典型位置：

- 群晖：`/volume1/docker/smdata`
- 绿联：`/共享文件夹/docker/smdata`
- 威联通：`/share/Container/smdata`
- 飞牛：`/vol1/1000/docker/smdata`

名字可自定义，下文统一叫 `smdata`。

### 2.1 控制台容器 spacemaster-console

- 镜像：`spacemaster-fnos:v3`
- 容器名：`spacemaster-console`（可自定义）
- 启动命令（各平台也叫执行命令 / Command）：保持默认，即 `python3 /opt/sm/peq_toggle_nas.py`，不用改
- 端口：容器 `8777` → 主机 `8777`
- 存储：挂载 `smdata` → `/opt/sm`（读写）
- 环境变量：不动

部署后浏览器打开 `http://<您的NAS内网IP>:8777` 应看到控制台页面。

### 2.2 修改Jellyfin容器配置

第 ① 步：停止 Jellyfin 容器。

第 ② 步：编辑 Jellyfin 容器，加两项：

- 存储：添加挂载 `smdata` → `/opt/sm`（读写）
- 环境变量：找到 `JELLYFIN_FFMPEG` 这一项
  - 有 → 把它的值改成 `/opt/sm/sm_wrapper.sh`（只改值，不删该项，它是官方镜像自带变量）
  - 假如没有 → 新增变量，名称 `JELLYFIN_FFMPEG`，值 `/opt/sm/sm_wrapper.sh`

第 ③ 步：保存并启动。

> 容器启动顺序：先启动控制台（2.1），确认 `smdata` 里生成了 `sm_wrapper.sh` 等文件，再启动 Jellyfin（2.2）。顺序反了 Jellyfin 启动时找不到 `sm_wrapper.sh` 会报错。

### 2.3 加 proxy（必须安装）

以后看电影访问proxy的端口地址，音效被空间大师优化；直接访问jellyfin原端口地址，音效不被空间大师优化。

- 镜像：`spacemaster-fnos:v3`
- 容器名：`spacemaster-proxy`
- 启动命令（执行命令 / Command）：填 `python3 /opt/sm/profile-proxy.py`（删掉栏里默认的控制台命令再填）
- 端口：容器 `8097`（ proxy 监听端口，可自定义）→ 主机 `8097`（proxy 访问端口，需确保端口未被占用，可自定义）
- 存储：挂载 `smdata` → `/opt/sm`（读写）
- 环境变量：新增两条
  - `SM_ROLE` = `proxy`
  - `UPSTREAM` = `http://<您的NAS内网IP>:<Jellyfin端口>`（您 NAS 上 Jellyfin 的真实访问地址+端口，必须带 `http://` 前缀；您的 Jellyfin 端口是8096 就填 8096）

使用：把您看电视 / 播放用的 Jellyfin 客户端里的「服务器地址」从原来的 `<Jellyfin端口>` 改成上面 proxy 的「主机端口」（例：`http://<您的NAS内网IP>:8097`，若您主机端口填的是 8098 就用 8098），账号和影片库不变。原来直连 `<Jellyfin端口>` 的地方照旧。

### 各平台 GUI 操作位置（在哪点）

- 群晖 Container Manager：Image 标签选中镜像 → Launch 进向导，高级设置里有 Port / Volume / Environment / Execution command 四项。编辑已有容器：Container 标签 → 选中 → Edit，分 Volume / Port / Environment 各 Tab 修改。
- 绿联 UGOS：Docker → 本地镜像选中 → 点「+」或双击创建容器，基础信息填名称与自动重启，高级里设端口 / 存储 / 环境变量。多容器部署推荐用「项目」粘贴 compose。
- 威联通 Container Station：Containers → Create 选镜像，高级设置里有 Commands / Entrypoint、Networks、Environments、Storage（Bind Mount Host Path）各 Tab。多容器用 Applications → Create 粘贴 compose。
- 飞牛 FnOS：Docker → 本地镜像选中 → ▶ 创建容器，基本设置 / 网络端口 / 存储位置 / 环境变量各页往下滚填。

---

## 第 3 步｜验证是否生效

进 NAS 文件管理器，看 `smdata/wrapper.log`（即您建的共享文件夹子目录），出现 `WRAP injected AF` 即代表音效已注入成功。

---

## 撤销（完全可逆）

1. 停并删 `spacemaster-console` 容器（若加了 proxy，一并停并删 `spacemaster-proxy`）。
2. 停 Jellyfin 容器 → 编辑：把 `JELLYFIN_FFMPEG` 的值改回默认 `/usr/lib/jellyfin-ffmpeg/ffmpeg`（不要删除这一项，它是官方镜像自带变量）、删掉 `/opt/sm` 挂载 → 保存并启动。
3. 可选删 `smdata` 文件夹。Jellyfin 与影片库无任何影响，回到装之前的状态。

---

## 排错

| 现象                                  | 可能原因                                               | 处理                                                                                                  |
| ----------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 8777 打不开                            | 控制台容器没起 / 端口冲突                                     | 看容器日志；或在端口设置里换一个主机端口                                                                                |
| `wrapper.log` 没有 `WRAP injected AF` | PEQ 没开 / 环境变量没生效 | 到空间大师控制台把 PEQ 开关打开；确认jellyfin容器中环境变量名拼写是 JELLYFIN_FFMPEG；重启 Jellyfin；确认jellyfin容器中启动命令已经改成python3 /opt/sm/profile-proxy.py |
| 听不出变化                               | 音频可能没走 ffmpeg                                      | 看 `wrapper.log` 的时间戳，确认是这次播放产生的；换一部片再试                                                              |
| 改完参数不生效                             | 没点保存 / 没重播                                         | 8777 点「保存配置」；退出影片重新播放                                                                               |

## 空间大师控制台页面说明 端口8777，空间大师控制台有以下功能：

- PEQ 开关：总开关，必须打开音效才生效。
- 房间尺寸 / 音箱系统类型 / 低音·中音·高音：空间声学校正参数。
- 频响曲线图：实时预览。
- 延时校准：目前仅独立 2.0 / 2.1 音箱可用，5.1 系统正在优化中。

## English

# SpaceMaster · Installation Guide (Synology / UGREEN / QNAP / FnOS universal)

> SpaceMaster only handles transcoded audio. Jellyfin subtitles / scraping / metadata / library / user history and all other features are unaffected.

> Prerequisite: you already run Jellyfin in Docker on your NAS (image `jellyfin/jellyfin` or `nyanmisaka/jellyfin`). SpaceMaster adds a sound-effect layer on top; it does not modify Jellyfin itself.
>
> ⚠️ Synology users: if you installed the native Jellyfin package from Package Center, it does not run in Docker and this method will not work. Install `jellyfin/jellyfin` in Docker first, then follow this guide.

SpaceMaster does not modify Jellyfin itself, your media library, accounts, the original `/config /cache /media` mounts, or any other settings. Uninstalling returns everything to its original state (see "Undo" below).

---

## Step 1 | Pull the image

Pull the image below to your NAS (entry points differ by platform, see parentheses):

`ghcr.io/gd-benzz/spacemaster-fnos:v3`

- Synology Container Manager: Registry tab → Settings → Add registry (enter `ghcr.io`) → search `spacemaster-fnos` to download; or Image tab → Add → Add from URL, paste the address above.
- UGREEN UGOS: Docker → Images > Image Registry → paste the ghcr address above to pull (see the in-system "Image acceleration & registry pull guide").
- QNAP Container Station: Create → enter `ghcr.io/gd-benzz/spacemaster-fnos:v3` (Advanced mode requires specifying registry and tag separately) → pull.
- FnOS: Docker → Local Images → + Add Image → Add from URL, paste the address above.

(The "Image Registry" page only searches Docker Hub by default; this name will not show up in a search — pull it from the URL / private registry entry.)

---

## Step 2 | Deploy (three containers)

On every platform, deployment has three parts: ① create the console container ② attach to your existing Jellyfin ③ add the proxy. First the "what to fill in" for each part, then "where to click" per platform.

### 2.0 Create the shared folder `smdata`

Under a NAS shared folder, create a subfolder `smdata`. This is the shared data area (sound-effect parameters, logs) for the console and Jellyfin. Typical locations per platform:

- Synology: `/volume1/docker/smdata`
- UGREEN: `/共享文件夹/docker/smdata`
- QNAP: `/share/Container/smdata`
- FnOS: `/vol1/1000/docker/smdata`

The name is customizable; below we uniformly call it `smdata`.

### 2.1 Console container `spacemaster-console`

- Image: `spacemaster-fnos:v3`
- Container name: `spacemaster-console` (customizable)
- Command (also called Execution command / Command): keep default, i.e. `python3 /opt/sm/peq_toggle_nas.py`, no change needed
- Port: container `8777` → host `8777`
- Storage: mount `smdata` → `/opt/sm` (read-write)
- Environment variables: leave unchanged

After deployment, open `http://<your NAS LAN IP>:8777` in a browser and you should see the console page.

### 2.2 Modify the Jellyfin container configuration

Step ①: stop the Jellyfin container.

Step ②: edit the Jellyfin container, add two items:

- Storage: add mount `smdata` → `/opt/sm` (read-write)
- Environment variable: find the `JELLYFIN_FFMPEG` item
  - If present → change its value to `/opt/sm/sm_wrapper.sh` (change only the value, do not delete the item; it is a built-in variable of the official image)
  - If absent → add a variable named `JELLYFIN_FFMPEG`, value `/opt/sm/sm_wrapper.sh`

Step ③: save and start.

> Container start order: start the console (2.1) first, confirm `sm_wrapper.sh` and other files are generated in `smdata`, then start Jellyfin (2.2). If reversed, Jellyfin will error at startup because it can't find `sm_wrapper.sh`.

### 2.3 Add the proxy (must install)

After this, accessing movies through the proxy's port address applies SpaceMaster optimization; accessing Jellyfin's original port directly does not.

- Image: `spacemaster-fnos:v3`
- Container name: `spacemaster-proxy`
- Command (Execution command / Command): enter `python3 /opt/sm/profile-proxy.py` (delete the default console command in the field first, then enter this)
- Port: container `8097` (proxy's listening port, customizable) → host `8097` (proxy access port, make sure it's free, customizable)
- Storage: mount `smdata` → `/opt/sm` (read-write)
- Environment variables: add two
  - `SM_ROLE` = `proxy`
  - `UPSTREAM` = `http://<your NAS LAN IP>:<Jellyfin port>` (the real access address + port of Jellyfin on your NAS, must include the `http://` prefix; if your Jellyfin port is 8096, enter 8096)

Usage: in your Jellyfin client (TV / player), change the "Server address" from the original `<Jellyfin port>` to the proxy's "host port" (e.g. `http://<your NAS LAN IP>:8097`; if you set the host port to 8098, use 8098). Your account and library stay the same. Direct connections to `<Jellyfin port>` still work as before.

### GUI operation locations per platform (where to click)

- Synology Container Manager: select the image in the Image tab → Launch to enter the wizard; advanced settings have Port / Volume / Environment / Execution command. To edit an existing container: Container tab → select → Edit, modify under the Volume / Port / Environment tabs.
- UGREEN UGOS: Docker → select local image → click "+" or double-click to create container; basic info for name and auto-restart, advanced for port / storage / environment variables. For multi-container deployment, use "Project" and paste compose.
- QNAP Container Station: Containers → Create to select image; advanced settings have Commands / Entrypoint, Networks, Environments, Storage (Bind Mount Host Path) tabs. For multi-container, use Applications → Create and paste compose.
- FnOS: Docker → select local image → ▶ Create container; scroll down through Basic settings / Network ports / Storage location / Environment variables pages.

---

## Step 3 | Verify it works

Open your NAS file manager and check `smdata/wrapper.log` (the subfolder of the shared folder you created). The line `WRAP injected AF` means the sound effect was injected successfully.

---

## Undo (fully reversible)

1. Stop and delete the `spacemaster-console` container (if you added the proxy, also stop and delete `spacemaster-proxy`).
2. Stop the Jellyfin container → edit: change the `JELLYFIN_FFMPEG` value back to the default `/usr/lib/jellyfin-ffmpeg/ffmpeg` (do not delete this item; it is a built-in variable of the official image), remove the `/opt/sm` mount → save and start.
3. Optionally delete the `smdata` folder. Jellyfin and your media library are completely unaffected — back to the pre-install state.

## Troubleshooting

| Symptom | Possible cause | Fix |
| --- | --- | --- |
| 8777 won't open | Console container not up / port conflict | Check container logs; or use a different host port in port settings |
| `wrapper.log` has no `WRAP injected AF` | PEQ off / env var not effective | Open the PEQ switch in the SpaceMaster console; confirm the env var name in the Jellyfin container is spelled `JELLYFIN_FFMPEG`; restart Jellyfin; confirm the **proxy container's** start command is `python3 /opt/sm/profile-proxy.py` |
| No audible difference | Audio may not be going through ffmpeg | Check the timestamp in `wrapper.log` to confirm it was produced by this playback; try another file |
| Changes not taking effect | Forgot to save / forgot to replay | Click "Save config" at 8777; exit the movie and play again |

## SpaceMaster console page (port 8777)

The SpaceMaster console has the following functions:

- PEQ switch: master switch; must be on for the effect to work.
- Room dimensions / speaker system type / bass · mid · treble: room-acoustics correction parameters.
- Frequency response chart: real-time preview.
- Delay calibration: currently available for standalone 2.0 / 2.1 speakers only; 5.1 system is under optimization.
